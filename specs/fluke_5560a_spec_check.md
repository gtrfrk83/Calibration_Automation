# Fluke 5560A standards sheet: check against the manufacturer's document

Document: Fluke 5560A Product Specifications, Dec 2022 Rev. 8, 6/26 (31 PDF pages; printed page n = PDF page n + 2). All page numbers below are PDF pages as stored in the sheet's `page` field.
Old sheet: git revision `794aeff` (SpecTrack export, author / approval "Tyler, Mike A, 2/10/2026", reference "OEM Manual"). New sheet: `specs/standards/fluke_5560a_standard.json`, written by `specs/build_5560a_standard_from_manual.py` (idempotent; every row carries its page). Generated by `specs/analyze_5560a_spec_check.py`.

Rules kept: the stored level is the 95 % column with divisor 2; period labels are `1 yr` (default) and `90 day`, as on the 3458A sheet; the 2 year columns and the 99 % columns are NOT loaded. No instrument command, limit or pass/fail logic is touched by this change.

## 2. The five most important differences

1. **Capacitance floors were 1000 times too small on four ranges.** 1.2nF: old 900 ppm of reading + 4e-15 F, document 900 ppm of reading + 4e-12 F (p.15); 12nF: old 900 ppm of reading + 5e-15 F, document 900 ppm of reading + 5e-12 F (p.15); 120nF: old 1000 ppm of reading + 3e-14 F, document 1000 ppm of reading + 3e-11 F (p.15); 120 µF: old 1200 ppm of reading + 2.5e-11 F, document 1200 ppm of reading + 2.5e-08 F (p.15). The old figures look like a unit slip (fF / pF / nF). Reports and TAR at capacitance points in those ranges change (section 5).
2. **2-wire resistance floors** at 12 ohm and 1200 Mohm: 12 Ohm: old 19 ppm of reading + 0.002 ohm, new 19 ppm of reading + 0.00225 ohm; 1200 MOhm: old 3100 ppm of reading + 300000 ohm, new 3100 ppm of reading + 102000 ohm. The document prints no 2-wire table; the new floors are COMPUTED from the printed formula (24 h floor + 5 uV / lowest specified stimulus current, pp.11-12). Unverified against a printed 2-wire figure.
3. **AC voltage 1.2 V, 5 Hz to 10 Hz**: old 680 ppm of reading + 7.5e-05 V, document 680 ppm of reading + 7e-05 V (p.6) (the same 75 vs 70 uV difference already noted for the 34410A suitability check in NOTES.md).
4. **Duty cycle**: the old sheet held three `input` rows (duty cycle MEASURED, 0.05 % of reading, old p.12). The document is for a source and prints no input duty figure, so those three rows are removed. The document prints the OUTPUT duty uncertainty (0.02 % of period + 100 ns at 50 %, 0.05 % of period + 100 ns for 10 % to 90 %; p.24), stored as three new output rows at 1 kHz (0.03 % / 0.06 %DC; at other frequencies the 100 ns term differs, see the problems list). The duty points of the 87V catalogue do not read these rows: `uncertainty_budget` has no DUTY lookup and `tartur` gives DUTY no ratio.
5. **107 rows added**: thermocouple types B, C, D, E, G, L, N, R, S, T, U, BP, XK (J and K existed), the ten RTD types, band splits (for example ACV / ACI frequency bands printed separately), and every row now has a 90 day figure. The old note 1 ("NOT checked against a 5560A specification document") no longer applies; the old approval ("Tyler, Mike A, 2/10/2026") is NOT carried over because it approved a different sheet.

## 6. The 90 day rows change nothing for existing 1 yr reports

`StandardSpec.lookup` uses `period or self.period`, and `self.period` is the standard's stored default, `1 yr`. A 90 day figure is used only when a caller passes `period="90 day"` explicitly or the owner changes the standard's default period; no procedure or report does either. The 1 yr spec is listed first in every row (three tests and the editor read `specs[0]`). ## 7. How the JSON reaches lab_registry.sqlite3, and what happens on the owner's machine

Tested on temporary databases (this script, `deployment_test`):

- **Owner database holds the OLD sheet**: seed loaded 1 standard(s); 147 rows.
- **Owner edits**: one asset link (A-1234), divisor set to 2.0 explicitly, one row edited (capacitance resolution).
- **1. git pull of the NEW JSON, program started (sm.seed over the same database)**: seed loaded 0 standard(s); rows still 147; assets [('A-1234', 'SER001')]; edited rows 1; log entries 3 -> 3. Nothing changes: seed skips a model that is already in the database.
- **2. Standards Specs > Import JSON with the NEW file (import_data, replace=True, no confirmation dialog)**: standard id 1 -> 2; rows 256; assets [] (the cascade deleted the link); edited rows 0; divisor field 2.0 (kept from the old row); period 1 yr (kept); approved_by ''; change-log entries for the new id: 1 (entries of the old id 1 stay in spec_changes, orphaned).

Reading of the code:

- `specmanager.seed()` (called when Standards Specs opens, and by `uncertainty_budget.build`, `tartur.standard_accuracy` and the engines) loads a `specs/standards/*_standard.json` only when its model is NOT in the database. A machine that already holds a 5560A keeps its rows, edits, assets and log. `sync_confidence` fills a missing confidence level only.
- Therefore **committing this JSON changes nothing on an existing owner database**; only a machine without a 5560A (new install, new database) gets the new sheet.
- The only code path that replaces it is the manual Standards Specs > Import JSON (`import_data(replace=True)`): it deletes the standard row, which cascades to the spec rows and the asset links (`standard_assets`), and inserts the new sheet. It keeps only the divisor and the default period; hand edits (`edited` rows, resolutions) and the asset links are lost, approved_by / approve_date come from the file (blank here), and there is NO confirmation dialog. The change log keeps an `import` entry for the new id, and the old id's entries stay in `spec_changes`.
- The spec editor's `rebuild_sheet` is an in-place resync that keeps edits, but it runs only for a documented edit of a spec file made in the editor; it is not a deployment path for this change.
- No existing machinery was run against the owner's database, and none will silently overwrite owner edits as long as nobody uses Import. The decision how to update a database that already holds the old 5560A sheet is left to the owner (question 8).

## 8. What the document does not give, or the schema cannot hold

- [warn] standard: Source: Fluke 5560A Product Specifications, December 2022, Rev. 8, 6/26 (English), 31 pages. Row "page" fields are PDF page numbers (printed page n = PDF page n + 2).
- [warn] standard: Approval: no author or approval is recorded. The previous sheet (a SpecTrack export) carried author and approval "Tyler, Mike A, 2/10/2026"; that approval was for the SpecTrack sheet, not for this rebuild from the document, so the fields are blank until the owner approves it.
- [warn] standard: Periods: only 90 day and 1 yr (95 % column, divisor 2). The document's 2 y columns and its 99 % columns are not loaded (owner decision). The default period of the standard stays 1 yr; a 90 day figure is used only when a caller asks for period="90 day".
- [warn] Frequency: The document prints ONLY a "2 Year Absolute Uncertainty" (+/-2.5 uHz/Hz, printed p.10); no 90 day or 1 yr figure exists. The previous sheet's value (2.5 ppm) is kept under "1 yr" so frequency lookups still work (a 2 year figure also bounds the 1 year one); no 90 day row is invented. Owner to confirm.
- [warn] Frequency: The previous sheet's amplitude qualifier [V 0 to 100] is dropped: the document gives no amplitude dependence for the frequency uncertainty. Resolution bands (printed p.10) are not stored.
- [warn] Frequency [Duty Cycle]: The document prints no period for the duty cycle uncertainty and gives it for 10 % to 90 % only (0.02 % of period + 100 ns at 50 %; 0.05 % of period + 100 ns otherwise, printed p.24). The previous sheet's three rows (1-49 %, 50 %, 51-99 %, rel 0.05 %, direction input) are replaced by rows for 50 %, 10-49 % and 51-90 % in %DC at 1000 Hz (direction output: the 5560A sources the square wave); 1-10 % and 90-99 % have no figure. The 100 ns term depends on frequency (0.01 %DC at 1 kHz only).
- [warn] Resistance [2-Wire]: The 2-wire floors are COMPUTED by the builder (24 h floor + 5 uV / lowest specified stimulus current, printed pp.11-12); the document prints no 2-wire table. The previous sheet differs at 12 ohm (0.002 vs 0.00225) and 1200 Mohm (300 kohm vs 102 kohm); the other seven agree with the formula.
- [warn] Resistance: Floors stored are the 24 h zero (+/-1 degC) column; the 14 d zero (+/-5 degC) floors are not stored. Floor scaling for stimulus currents below / above the specified range (printed p.12) and the RF-field increase of 150 % / 160 % (printed p.11) are not stored.
- [warn] Resistance, Capacitance, Inductance: Four-wire compensation is assumed for the stored resistance, inductance (and COMP OFF for capacitance) figures; the COMP adders printed with those tables are not stored.
- [warn] Voltage, AC: The ACV 12 mV range minimum output (1 mV, note 7), the 100 kHz - 300 kHz 70 V limit of the 120 V range (note 8) and External Sense (note 6) are stored as notes only (notes 6 - 8).
- [warn] Voltage, AC / Current, AC: Bands printed against 40.01 Hz (1.2 V, 12 V, 120 V ranges) are stored from 40.01 Hz up, as printed; 40 Hz belongs to the 10 Hz - 40 Hz row. Neighbouring bands share their border value; the larger limit is used on a border (specmanager rule).
- [warn] Temperature: The J and K "input" rows are kept from the previous sheet: the document prints one TC table (source), not a measure table. Values equal the printed J / K figures. Direction "input" is unverified.
- [warn] Temperature: Thermocouple and RTD specifications exclude thermocouple / sensor error and are valid for tcal +/-5 degC (printed pp.15, 18). Types B C D E G L N R S T U BP XK and all RTD tables are NEW on this sheet (not in the previous one).
- [warn] standard: NOT LOADED (the document prints them; owner to decide whether to add): resolution tables (DCV p.3, ACV p.5, DCI p.7, ACI p.9, resistance p.12, capacitance p.13, inductance p.14, TC 0.01 degC / RTD 0.001 degC) - the sheet row field "resolution" stays blank, so no resolution term enters the budgets (as before); operating characteristics (stability, noise, distortion, compliance, output impedance, load limits); ACI compliance adders; ACV extended bandwidth (0.01 Hz - 3 Hz 5 %, printed p.23); ACV / ACI square wave accuracy (pp.24-25); ACV DC offset (p.26); Aux voltage DC / AC sine / AC square (pp.26-28); phase (p.11); AC / DC power and dual output limits (pp.21-22); harmonics (p.23); TC voltage source / measure in linear modes (p.17); 5560A with 52120A current specifications (pp.28-29); the 2 y and 99 % columns of every table.
